# 编码规范（Rules）

## 默认规则（创建即生效）
- 程序设计要分层（接口层 / 业务层 / 数据访问层），避免把业务逻辑堆在入口文件。
- 唯一数据通道原则：全项目只有 internal/store 一个包可以直接执行 SQL。接口层、知识库层、心跳巡检层一律通过 store 包提供的操作方法访问数据，禁止自行拼 SQL 或打开数据库连接。
- 禁止绕过 SQLite 直接读写库文件；禁止引入外部向量数据库、外部缓存、外部搜索引擎等第二存储系统。
- 配置信息要放在统一位置（internal/config 包与 config.yaml），禁止在代码中散落硬编码。
- 关键流程必须有明确错误处理，禁止静默吞错。
- 对外输入必须先校验（参数、文件、请求体），再进入业务逻辑。
- 函数保持单一职责，复杂函数应拆分为小函数。
- 变更前先确认范围，变更后必须有最小可复现验证。

## 命名规范
- 使用有语义的命名，禁止 tmp、test1 等无意义命名进入正式代码。
- 包名小写单词，不用下划线；类型与方法命名遵循 Go 社区惯例。

## 代码风格
- 保持一致的格式化风格（gofmt）；优先小函数、低耦合。
- 接口声明在调用方一侧，不提前抽象。

## 错误处理
- 错误信息应可定位（包含上下文），并返回明确失败状态。
- 跨层传递错误用 %w 包装，保留原始错误供上层判断。

## 日志与注释
- 日志记录关键路径，用 log/slog 结构化输出。
- 注释写为什么，不重复做了什么；不留被注释掉的旧代码。

## 安全与隐私
- 禁止提交密钥、令牌、密码等敏感信息；密钥只走配置文件或环境变量，配置文件中的密钥在日志与回显中必须脱敏。
- 表名、字段名、排序字段等数据库标识符必须走白名单校验，禁止把用户输入直接拼进 SQL 标识符位置；参数值一律使用占位符绑定。
- 默认只监听本机回环地址；对外暴露、HTTPS、鉴权均需显式配置；公网监听且未启用鉴权时要求配置 acknowledge_risk: true。

## 测试与回归要求
- 至少覆盖主流程与一个失败分支。
- 存储层测试使用临时目录中的真实库文件，不用内存库代替文件库的备份与迁移测试。
- 涉及数据库的改动必须跑通迁移与备份恢复验证。

## 禁止事项（反模式）
- 禁止跨层直接调用导致耦合失控。
- 禁止在接口层或业务层直接构造 SQL 字符串。
- 禁止把上层组件（网盘、博客等）的业务逻辑写进本项目的代码。
