# 项目总目标（Goal）

## 项目背景
- 业务场景：个人自托管的一体化数据底座。SQLite 数据库服务与知识库两个功能深度绑定在一个进程、同一份 SQLite 数据文件里，做到零失误数据交互。项目本身也是后续网盘、博客等组件的公共数据基础。
- 目标用户：开发者本人（单用户自托管），预留少量可信使用者接入的可能。

## 总目标
用 Go 实现一个进程，对外提供两类标准 REST/JSON API 接口：
1. 数据库服务接口：把 SQLite 的安全能力（表管理、按条件读写、全文检索）包装成受控的 HTTP 接口，同时作为将来网盘、博客等上层组件的通用数据底座。
2. 知识库接口：文档入库、分块、向量嵌入、语义加关键词混合检索、带引用的问答。

全部数据保存在 SQLite 数据库文件中，不引入第二套存储系统。外部模型适配层负责接入对话与向量嵌入两类外部模型供应商。心跳巡检层负责数据库的定期完整性检查、备份、文件一致性校验——纯规则代码，不调用大模型。将来正式 agent 通过 HTTP API 或 MCP 远程接入，本项目不内置 agent。

## 成功标准
- 功能成功标准：
  - 单进程启动后可完成：建表、插入、按条件查询、更新、删除、全文检索（中文可用）。
  - 知识库可完成：上传文档、自动分块、生成嵌入并入库、语义加关键词混合检索、基于检索结果调用外部模型生成回答。
  - 心跳巡检可完成：定时检查数据库完整性、备份状态、外置文件一致性；异常时写记录。
  - 底座能力可验证：通用表操作接口（结构化查询 + RESTful 路由）可用，且不包含任何上层业务逻辑。
- 质量成功标准：
  - 备份与恢复经过一次真实演练。
  - 数据库迁移机制经过一次真实升级。
  - 服务以静态单二进制方式构建，不经 CGO 也能完整运行。

## 范围边界（做 / 不做）
- 做：
  - 受控的通用表操作接口（结构化查询 + RESTful 路由两层）与知识库接口，带 JWT 鉴权与 HTTPS。
  - SQLite 官方接口作为唯一数据通道：全文检索（FTS5 + gse 中文分词）、向量检索（sqlite-vec 虚拟表），全部走 SQL。
  - 外部模型通用适配：对话与嵌入两类接口，多家供应商可配置切换。
  - 心跳巡检：定时检查、异常记录、自动重建索引。
  - 外置大文件目录加库内路径索引，内容指纹校验。
  - 底层组件：定时任务、迁移、备份、审计。
- 不做：
  - 不内置 agent（语义能力在知识库模块直接调 LLM 适配层；正式 agent 是外部接入）。
  - 不做多用户权限体系。
  - 不做分布式、多实例、数据同步。
  - 不引入外部向量数据库、外部缓存、外部搜索引擎等第二存储。
  - 不在数据库里跑本地推理模型。
  - 不实现网盘、博客等上层业务，只提供它们所需的地基。

## 约束条件
- 技术约束：
  - 语言 Go（1.22+）；数据库驱动 modernc.org/sqlite（纯 Go，不需要 CGO），配套 modernc.org/sqlite/vec 向量检索。
  - 路由用 go-chi/chi/v5（100% 兼容 net/http，生产级，无外部依赖）。
  - 鉴权用 golang-jwt/jwt/v5（标准 JWT 库，HMAC-SHA256 签名）。
  - 日志用 log/slog；配置用 YAML。
  - 所有数据必须经 SQLite 官方接口与 SQL 命令读写，禁止绕过 SQLite 直接改库文件。
  - HTTP 服务默认只监听本机回环地址；对外暴露、HTTPS、鉴权均默认关闭，需显式配置；公网监听且未启用鉴权时要求配置 acknowledge_risk: true。
  - 外部模型供应商可配置化，密钥只走配置文件或环境变量，不进代码库。
- 时间约束：分阶段交付，先地基后知识库，每阶段独立可用。
